# Project Notes

- Python 3.11+ FastAPI application; install dependencies with `pip install .` from this directory. The `tzdata` dependency supplies IANA time zones on Windows. The frontend calls the service through its same-origin Next.js reverse proxy using a short-lived Spring-issued assistant JWT.
- `app/main.py` defines `GET /health` and `POST /api/assistant/chat`; Swagger UI is served at `/docs`. The chat endpoint rejects requests outside this app's RTO planning, user-visible events, and team attendance scope before calling Bedrock, including requests about another platform, company, or service; the Bedrock system prompt reinforces the same boundary.
- Chat verifies JWT signature, issuer, audience, expiry, subject, and `assistant:chat` scope with the shared RSA public key. The initial Bedrock system prompt tells the assistant to continue prior turns and explain recommendations from available facts; it limits RTO planning to tomorrow through the end of the following month, and honors weekday preferences when enough eligible dates remain. The frontend sends up to eight recent U/A turns (up to 6,000 characters), which Python converts into Bedrock conversation turns. Model replies are checked so past and same-day dates are not returned as new schedule options. Bedrock Converse can select read-only tools for visible events, other platform members' daily RTO counts, and the user's saved office days. Python validates ranges and calls fixed Spring endpoints with the same token. Read-only data ranges run from the first of the current month through the end of next month; new planning suggestions begin tomorrow, and no write tools are available. Past attendance results must be identified as historical and not upcoming. Monthly RTO counts are total targets unless the user says “additional” or “more”; Python reads the target from the latest user turn only and counts saved days in the target month. Explicit “N more” planning follow-ups inherit the prior target month, exclude previously suggested dates; when prior planning context is missing and the user says today is unavailable, use the current month and exclude today, and honor weekday ranges. Monthly recommendations require fresh schedule, event, and team-count lookups; Python selects valid dates from those results, honors preferred weekdays before falling back to other weekdays, prioritizes required events and teammate attendance within each group, and uses weekends only when weekdays cannot meet the remaining target. Answers name saved dates, give the exact remaining count, and explain each suggested date using tool facts. ISO dates from the model are normalized to readable dates with correct weekday labels. Direct event questions and event refresh follow-ups require a fresh Spring lookup; event refreshes reuse the prior event question's range. Direct team-attendance questions require a fresh counts-tool lookup. Replies stay concise; the service does not receive the session cookie or persist schedules.
- Planning follow-ups retain the selected month, carry forward weekday preferences, honor unavailable weekdays and dates, and rerun the read-only data lookups when the user revises constraints. If too few dates remain, the reply asks which constraint to relax; ambiguity that changes the plan should prompt a focused question.
- Configure `JWT_ISSUER`, `JWT_AUDIENCE`, `JWT_PUBLIC_KEY_PATH`, and `SPRING_BACKEND_URL` in `.env`; generate local signing keys with `python scripts/generate_local_jwt_keys.py` from this directory. `BEDROCK_MODEL_ID` defaults to `amazon.nova-micro-v1:0`; AWS region comes from `AWS_REGION` or `AWS_DEFAULT_REGION`.
- Request validation failures log the endpoint, content headers, and field errors without logging prompt or context values.
- The Next.js server reverse-proxies chat to this service, so browser CORS is not needed for chat. The service binds to `127.0.0.1:8010` locally; see `README.md` for setup.
